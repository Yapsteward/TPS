01 / System Overview

Transforming Telegram into a Unified Multimodal Brain

Brian AI is an autonomous, multi-modal personal assistant deployed on Telegram to solve the modern bottleneck of on-the-go communication. In today's fast-moving environments, team members frequently switch between sending quick text queries and recording complex voice memos while in transit.

Prior to this implementation, handling voice notes required active human playback, manual note-taking, and slow manual replies. Conventional Telegram bots either failed entirely when receiving audio memos or operated purely as stateless single-turn scripts that forgot context instantly.

This project established a unified multi-modal AI architecture built inside n8n. By pairing an intelligent MIME-type router with Google Gemini Speech-to-Text, Gemini Chat reasoning, and Window Buffer Session Memory, Brian AI transforms incoming audio and text into structured, context-aware dialogues in real time.

02 / Bottlenecks

The Friction in Traditional Telegram Workflows

🎙️

On-The-Go Voice Memo Bottleneck

Team members frequently send voice notes when driving. Listening, extracting items, and drafting replies manually caused massive delays of 15 to 45 minutes per memo.

🧠

Loss of Conversational Memory

Conventional chatbots treat every incoming webhook as an isolated transaction. Users had to repeat background details and prompt context with every follow-up question.

💰

Cost & Latency Waste

Naive AI workflows run every payload through heavy transcription routines, resulting in unnecessary API spend and latency spikes on simple text messages.

🧩

Fragmented Architectures

Maintaining separate bots for voice and text resulted in duplicated system prompts, inconsistent bot personalities, and fractured user databases.

An IF node checks the MIME type of the incoming payload. Text messages bypass transcription to save money, while voice notes are routed to the audio branch.
